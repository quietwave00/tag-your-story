# GENRE-GRAPH-UI-001 — 정적 데이터 기반 장르 그래프 탐색

- 수정 후 빌드·테스트·lint는 직접 실행하지 않았으며 사용자 재실행 결과를 기다린다.

## 데이터 기준과 화면 목표

입력: `agents/client/data/genre-graph/musicbrainz-genre-graph-5c2684b8-f38e-4c56-a3a1-a56d2a79814a.json`.
원본 전체 파일을 `tag-note-react/public/data/genre-graph.json`으로 복사해 화면 진입 시에만 읽는다. partial 파일은 검증 자료로만 사용한다. 스냅샷 갱신 시 원본과 배포 파일을 함께 교체한다.

분석 결과: 2,222개 노드, 3,538개 관계(SUBGENRE 1,603 / INFLUENCES 1,753 / FUSION 182), 방향을 제외한 연결 집합 292개, 최대 집합 1,889개, 연결 없는 노드 268개. hip hop과 pop은 각각 고유 이웃 98개다. 다중 부모와 영향 순환을 보존한다.

데이터 분석은 밀집도·배치·레이블 가독성에 활용한다. 별도 분석 대시보드, 인기도 순위, 음악적 유사도 점수를 만들지 않는다.

## 화면과 상호작용

- 공통 헤더 장르 메뉴와 `/genres` 경로를 추가한다. 기존 최대 폭·글꼴·무채색 디자인을 재사용한다.
- 검색, 관계 유형 필터, 전체 보기, 그래프, 선택 패널, 범례와 데이터 정보 순서로 구성한다.
- 최초에는 모든 노드가 들어오는 전체 보기. 선택 시 해당 장르와 필터에 맞는 직접 이웃을 강조하고 나머지는 흐리게 유지한다. 호버는 카메라를 움직이지 않는다.
- 데스크톱 우측 320px 패널, 768px 미만에서는 높이 최대 45dvh의 접이식 하단 패널. 패널을 제외한 그래프 영역으로 카메라를 맞춘다.
- 선택 이동 300ms, 움직임 줄이기에서는 즉시 이동. 드래그·휠·핀치와 확대·축소 버튼을 지원한다.
- 선택 ID는 `?node=`에 저장하고 브라우저 뒤로가기·앞으로가기와 직접 링크를 지원한다. 잘못된 ID는 안내 후 해당 파라미터만 제거한다. 전체 보기는 선택과 필터를 초기화한다.
- 필터 변경은 카메라·노드 배치를 유지한다. 모든 유형을 꺼도 노드 검색과 선택이 가능하다.
- 검색은 정확 일치→접두→부분 일치, 이름·ID로 동률 정렬한다. 20개씩 더 보기와 방향키·Enter·Escape를 제공한다.

## 배치와 데이터 해석

- Web Worker에서 연결 집합별 힘 기반 배치를 계산하고 서로 겹치지 않게 배치한다. 가장 큰 집합부터 배치하며 고립 노드는 별도 격자로 둔다. ID 순서로 초기 위치를 고정하고 안정화된 좌표를 Canvas에 전달한다.
- 고유 이웃 수에 로그 비례하여 노드 반지름 3~8px. 선택 테두리는 별도 표현한다.
- 이름 우선순위: 선택→호버→직접 이웃→연결 수→ID. 화면 좌표의 공간 격자로 이름 충돌을 검사한다. 선택 이름을 유지하고 겹치는 나머지 이름은 숨긴다. 모든 장르는 검색·관계 목록에서 접근 가능하다.
- 기본 선은 회색, 선택 관계만 절제된 유형별 색을 쓴다. SUBGENRE 상위→하위, INFLUENCES 영향 제공→수용, FUSION 재료→결과. 영향은 물결선, 복수 관계는 곡률로 구분한다. FUSION 배치 거리는 기본보다 짧게 한다.
- 위치·크기가 인기도나 청취 유사도를 의미하지 않음을 데이터 정보에 명시한다.
- 선택 패널은 원문 장르명·출처·고유 이웃 수·관계 수·6방향 그룹·원본 evidence를 제공한다. 필터 적용 건수와 전체 건수를 구분하고 관계 없는 장르를 누락하지 않는다.
- COMPLETE는 수집 작업 완료를 뜻하며 모든 음악 장르를 망라한다는 의미가 아니다. PARTIAL은 제한된 자료임을 안내한다.

## 구현 경계와 계약

- service: 정적 JSON fetch 및 취소. feature: 검증·정규화·인접 인덱스·검색·Worker 배치·Canvas·선택 패널. page: 조립과 URL 동기화.
- 원본 데이터와 좌표를 변경하는 렌더러 객체를 분리한다. 관계 ID는 `(source,target,type)` 조합으로 생성한다. 스키마 불일치·중복 ID·없는 노드 참조는 실패로 표시하고 재시도를 제공한다.
- `react-force-graph-2d`, Worker용 `d3-force-3d`를 정확한 버전으로 lockfile에 고정한다. React 19/Vite 실행 호환성은 사용자 검증 대상이다.
- 번역은 `genres` namespace의 ko/en 리소스에 둔다. 장르명·검색어·출처 원문을 번역하지 않는다.
- 기존 AppLayout·routes·visually-hidden을 재사용한다. 그래프는 상세 문서가 아닌 독립 탐색 화면이므로 상세 스크롤 훅·BackButton을 강제 적용하지 않는다.
- 접근 가능한 서버 003 및 ADR-035는 초안·미구현으로 확인되었다. 이번 작업은 새 서버 endpoint나 관리자 권한을 추정하지 않는다. 지정 migration-server 및 실행 응답을 검증한 것으로 기록하지 않는다.

## 후속 관리자 요구 보존

서버 공개 Api→Controller→DTO와 신뢰 가능한 관리자 권한 계약이 확정된 뒤 별도 Plan으로 진행한다. 기존/신규 장르 선택→대상·유형·방향·사유 확인→저장 흐름을 유지한다. 장르 생성 후 관계 실패 시 생성 결과를 보존하고 관계만 재시도한다. 버전 충돌 시 입력 보존·최신 조회·재확인을 제공한다. 삭제·병합은 별도 범위다.

## 테스트와 수용 기준

- 모델: 방향·다중 부모·순환·복수 유형·고유 이웃·고립 노드·자기참조·검색 순서·잘못된 참조·부분/빈 자료.
- 화면: URL 복원·잘못된 ID·필터 유지·전체 보기·키보드 검색·관계 이동·뒤로가기·닫기 포커스·실패와 빈 결과 구분.
- 회귀: 기존 검색 링크를 유지하면서 장르 메뉴 추가. 원본 API 콘텐츠는 그대로 표시.
- 브라우저: 전체 데이터에서 첫 화면·반복 포커스·고유 이웃 98개·긴 이름·필터·근거 링크·모바일 패널·핀치·키보드·움직임 줄이기 확인.
- 성능: DevTools에서 첫 표시·Worker 배치 시간과 이동 프레임 시간 측정. 데스크톱 60fps·모바일 30fps 목표, 브라우저·기기·뷰포트·실측 결과를 기록한다. 현재 성능 실측은 하지 않았다.

사용자 실행:

```bash
cd tag-note-react
npm ci
npm run test
npm run lint
npm run build
```

코드·diff 검토와 변경 파일 공백 검사를 수행했다. Windows worktree의 CRLF는 Git `core.whitespace=cr-at-eol` 설정으로 구분했다.

Codex는 빌드·테스트·브라우저 자동 검증을 실행하지 않았다. 설치는 lockfile만 갱신했으며 사용자 `npm ci`가 필요하다. 실행 결과와 사용자 화면 확인 후 완료 여부를 결정한다.

## 후속 사용자 변경 — 그래프 집중 화면

- 사용자 지시로 선택 aside를 화면에서 제거한다. 장르 설명·랜덤 곡은 향후 범위이며 현재 API나 가짜 콘텐츠를 추가하지 않는다. 위 선택 패널 계획은 이 변경으로 대체된다.
- 렌더링된 장르 타이틀의 실제 영역도 선택 대상으로 처리하며 드래그를 클릭으로 처리하지 않는다.
- 방향 화살표를 선택 관계 13px, 일반 관계 10px로 확대한다.
- 선택 노드 자체를 정확히 중앙에 두고 주변 노드까지 보이는 줌으로 750ms 보간 이동한다. 새 선택과 직접 조작은 진행 중 이동을 취소한다. 움직임 줄이기에서는 즉시 이동한다.
- 장르 화면에서 전역 body::after 하단 안개 그라데이션을 해제한다.
- 키보드 탐색은 전체 검색으로 유지한다. 기존 aside·관계 목록 테스트는 변경된 화면에 맞춰 갱신한다. 사용자 실행·시각 검증 대기.
