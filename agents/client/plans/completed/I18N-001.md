# I18N-001 — Korean/English Global UI Localization

## Status

- Completed / 2026-10-14 Human Review 승인 및 사용자 검증 확인
- 대상: `tag-note-react/`

## Goal

현재 React SPA의 사용자 인터페이스를 한국어와 영어로 전환할 수 있게 한다. 번역 리소스, 언어 감지/저장, React 연결, 언어 선택 UI를 한 경계에 모아 새 화면이 같은 규칙으로 확장될 수 있게 한다.

## Product Rules

### 지원 언어

- `ko`: 한국어
- `en`: English
- 감지 순서: 사용자가 저장한 선택 → 브라우저 주 언어 → English fallback
- `ko-KR`, `en-US`, `en-GB` 같은 지역 코드는 각각 `ko`, `en`으로 해석한다.
- URL에는 locale segment나 `?lang=`를 추가하지 않는다. 기존 route와 외부 링크 계약을 유지한다.

### 번역 대상

- Header/navigation, 언어 선택기
- 페이지/section 제목
- 버튼, 입력 placeholder, form label
- loading, empty, validation, confirm, 오류 안내
- pagination 및 접근성용 `aria-label`
- `Artist`, `Album`, `Track ID`, `Like`처럼 UI가 붙이는 metadata label
- 알림 문장 템플릿
- 이미지 대체 텍스트의 UI 부분

### 번역하지 않는 콘텐츠

- User Tag와 System Tag의 이름
- 검색 keyword
- 트랙, 앨범, 아티스트 이름
- Spotify/외부 provider가 제공한 metadata 문자열
- 닉네임
- Board/Comment/Reply 본문
- 사용자가 입력 중인 form 값과 업로드 파일명
- 서버가 반환한 콘텐츠성 문자열

동적 콘텐츠는 번역 문장에 interpolation할 수 있지만 값 자체를 번역 key로 조회하지 않는다. 예를 들어 알림 publisher 이름과 Track 제목은 원문을 유지하고 주변 문장만 번역한다.

## Technical Decision

### Library

다음 패키지를 사용한다.

- `i18next`: locale, fallback, resource와 interpolation 관리
- `react-i18next`: `useTranslation`을 통한 React 구독과 재렌더링
- `i18next-browser-languagedetector`: localStorage와 browser language 감지

공식 문서가 안내하는 `supportedLngs`, `fallbackLng`, `load`, namespace 및 `useTranslation` 구성을 따른다. 감지 plugin의 기본 query/hash/cookie 동작은 사용하지 않고 `localStorage`, `navigator`만 허용한다.

### State ownership

- 현재 언어의 Source of Truth는 i18next instance로 둔다.
- 별도의 React Context나 `languageStore`를 만들지 않는다.
- 언어 변경은 `i18n.changeLanguage(language)`만 사용한다.
- 선택값은 `tagnote.language` localStorage key에 저장한다.
- 언어 변경 시 `<html lang="ko|en">`을 동기화한다.
- locale 변경 때문에 API를 다시 요청하지 않는다.

### Resource structure

```text
tag-note-react/src/
  i18n/
    index.js
    languages.js
    locales/
      en/
        common.json
        auth.json
        home.json
        tracks.json
        boards.json
        community.json
      ko/
        common.json
        auth.json
        home.json
        tracks.json
        boards.json
        community.json
  components/common/
    LanguageSwitcher.jsx
```

Namespace 책임:

- `common`: navigation, 공통 action, pagination, generic loading/error, accessibility label, Contact
- `auth`: login, token sync, nickname 등록
- `home`: 검색 진입, 랭킹, 최근 태그
- `tracks`: 검색 결과, Track 상세와 metadata label
- `boards`: Board 상세/작성/수정, 파일과 form validation
- `community`: 댓글, 답글, 좋아요, 알림

한 key는 한 namespace만 소유한다. 동일한 의미의 `save`, `cancel`, `previousPage`를 feature마다 복제하지 않는다. key는 화면 문장 자체가 아니라 안정적인 의미 기반 경로(`board.form.validation.tagRequired`)를 사용한다.

초기 규모에서는 locale JSON을 정적으로 import해 bundle에 포함한다. 네트워크 backend와 runtime translation fetch는 추가하지 않아 첫 render의 번역 flash와 별도 실패 경로를 만들지 않는다.

## Implementation Scope

### 1. i18n foundation

- package dependency와 lockfile을 갱신한다.
- `src/i18n/index.js`에서 instance를 한 번만 초기화한다.
- `supportedLngs: ['ko', 'en']`, `fallbackLng: 'en'`, `load: 'languageOnly'`를 사용한다.
- React가 HTML을 escape하므로 interpolation의 이중 escape를 끈다.
- production에서 missing key를 원격 저장하지 않는다.
- 앱 render 전에 `src/main.jsx`에서 i18n 초기화를 import한다.

### 2. language switcher

- Header에 `KO / EN` 형태의 compact switcher를 추가한다.
- 현재 언어는 `aria-pressed`와 font weight/opacity로 표현하고 active underline은 사용하지 않는다.
- keyboard로 조작할 수 있는 native button을 사용한다.
- 기존 monochrome header와 mobile layout을 깨지 않는다.

### 3. UI string migration

다음 파일의 UI literal을 namespace key로 이동한다.

- `components/layout/AppLayout.jsx`
- `components/common/EmptyState.jsx`
- `components/common/PageHeader.jsx`
- `pages/HomePage.jsx`
- `pages/TracksPage.jsx`
- `pages/TrackDetailPage.jsx`
- `pages/BoardDetailPage.jsx`
- `pages/BoardEditPage.jsx`
- `pages/LoginPage.jsx`
- `pages/TokenPage.jsx`
- `pages/NicknamePage.jsx`
- `pages/ExceptionPage.jsx`
- `pages/ContactPage.jsx`
- `features/comments/CommentSection.jsx`
- `features/notifications/NotificationCenter.jsx`

현재 영어로 하드코딩된 `SEARCH`, `Artist`, `Cancel` 등도 번역 대상으로 포함한다. 브랜드명 `#tagnote`와 외부 서비스명 `GITHUB`, `SPOTIFY`, `INSTAGRAM`, `EMAIL`, `GOOGLE`은 고유명사로 유지할 수 있으며 주변 접근성 문구만 번역한다.

### 4. dynamic messages and formatting

- nickname 확인/가입 완료 문장은 interpolation을 사용하고 nickname은 원문을 보존한다.
- notification 문장은 publisher interpolation을 사용한다.
- Track으로 돌아가기 문장은 title interpolation을 사용한다.
- count가 문장에 포함되면 i18next plural 규칙을 사용한다.
- `createdAt`은 선택 언어를 전달한 `Intl.DateTimeFormat`으로 표시한다. 파싱할 수 없는 서버 값은 기존처럼 원문 fallback한다.
- 서버 `exceptionCode`를 화면에 노출할 필요가 생기면 명시적 code → translation key map을 사용한다. 서버 message나 콘텐츠를 자동 번역하지 않는다.

### 5. boundary enforcement

- API service/DTO mapper에는 `t()`를 넣지 않는다.
- translation key와 UI 문구 선택은 component 또는 UI 전용 formatter에서 수행한다.
- Tag/Track/Album/Artist/User content를 `t(dynamicValue)` 형태로 호출하지 않는다.
- CSS class, route, API request, storage의 기존 content 값은 locale 변경으로 바꾸지 않는다.

## Tests

현재 프론트엔드에 test runner가 없으므로 이 마일스톤에 필요한 최소 Vitest + React Testing Library + jsdom 설정을 함께 추가한다.

자동 테스트:

- 저장된 언어가 browser language보다 우선한다.
- 지원하지 않는 browser language는 English로 fallback한다.
- `ko-KR`과 `en-US`가 지원 base language로 해석된다.
- switcher가 언어, localStorage, `<html lang>`을 함께 변경한다.
- 언어 변경 시 route와 API request가 발생하지 않는다.
- navigation, validation, loading/error, confirm 문구가 양 언어로 표시된다.
- notification publisher, nickname, Track 제목과 Tag 이름은 locale 변경 후에도 동일한 원문을 유지한다.
- 두 locale의 namespace/key 집합이 일치한다.

정적 점검:

- JSX의 사용자 대상 한글/영문 literal을 검색하고 예외는 브랜드/고유명사/동적 콘텐츠로 분류한다.
- `t(variable)` 또는 API response를 translation key로 사용하는 패턴이 없는지 확인한다.

## Acceptance Criteria

1. 모든 route에서 Header의 KO/EN 전환이 즉시 적용된다.
2. 새로고침 후 사용자가 마지막으로 선택한 언어가 유지된다.
3. 첫 방문은 browser language를 사용하고 미지원 언어는 English로 표시된다.
4. `<html lang>`이 현재 resolved language와 일치한다.
5. 모든 사용자 대상 UI, validation, confirm, loading, empty, error, aria label이 한국어/영어 리소스를 사용한다.
6. Tag, 검색어, 음악 metadata, 닉네임, 게시글/댓글 콘텐츠는 언어 변경 전후 완전히 동일하다.
7. API endpoint, request/response, route path, 인증 및 storage content 계약은 변경하지 않는다.
8. locale key parity test, component tests, lint와 production build가 통과한다.
9. 360px와 desktop header에서 switcher가 navigation을 가리거나 overflow를 만들지 않는다.

## Non-goals

- 서버 데이터 번역 또는 번역 필드 추가
- 자동 번역 API 연결
- Tag/Track/Album/Artist 다국어 데이터 모델
- locale별 URL 또는 SEO routing
- timezone 선택 기능
- 한국어/영어 외 locale
- API/인증/상태 구조의 관련 없는 리팩토링

수동 확인:

1. browser language가 한국어/영어/미지원 언어일 때 첫 진입 언어를 확인한다.
2. KO/EN 전환 후 route를 이동하고 새로고침해 선택 유지 여부를 확인한다.
3. Home → 검색 → Track 상세 → Board 상세 → 작성/수정 → 댓글 → 알림 → 인증 화면을 양 언어로 확인한다.
4. 전환 전후 Tag, Track/Album/Artist, 닉네임, Board/Comment 내용이 변하지 않는지 확인한다.
5. mobile/desktop Header와 keyboard focus를 확인한다.

## Rollback

- i18n import와 switcher를 제거하고 component의 기존 literal로 복구할 수 있다.
- API, route, backend schema를 변경하지 않으므로 서버 rollback은 필요하지 않다.
