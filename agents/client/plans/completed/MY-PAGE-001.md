# MY-PAGE-001 — 마이 페이지 진입과 계정 화면

## 완료 처리 기록

- 2026-11-16 사용자 지시로 이 Plan의 관리 상태를 완료로 변경한다. 아래의 검증 대기 기록은 완료 처리 이전에 작성된 이력이다.
- `npm run test`, `npm run lint`, `npm run build` 및 실제 로그인·계정 화면 브라우저 검증 결과는 전달받지 않았다. 검증 통과로 기록하지 않는다.

## Human Review와 범위

- 2026-10-26 사용자가 로그인 후 EXIT 영역에 마이 페이지 진입을 추가하고, 내가 쓴 태그·좋아요한 글·로그아웃·설정·탈퇴 화면을 디자인하도록 직접 요청했다. 이 명시적 작업 범위를 Human Review 승인으로 기록한다.
- 기존 헤더와 인증 흐름을 유지하면서 `/my` 화면을 추가한다. 서비스 API는 좋아요 목록, 닉네임 변경, 탈퇴만 연결한다. 기존 로그아웃 호출을 재사용한다.
- `내가 쓴 태그`의 사용자별 목록 API는 접근 가능한 서버 Controller에서 확인되지 않았다. 준비 중 상태로 표시하며 임의의 게시글이나 로컬 데이터를 개인 목록으로 표시하지 않는다.
- 2026-10-26 사용자 후속 요청으로 헤더 EXIT 버튼을 제거하고 닉네임이 표시되는 마이 페이지 링크로 대체한다. 마이 페이지의 장식 문구와 소개 문장을 제거하고 제목에도 닉네임을 표시한다.

## 계약 근거와 위험

- `migration-server` worktree는 이 환경에서 찾을 수 없다. 지정 worktree의 최신 계약을 검증했다고 주장하지 않는다. 접근 가능한 `tagnote-api`의 `LikeApi` → `LikeController` → `LikedBoardResponse`, `UserApi` → `UserController`를 순서대로 확인했다.
- `GET /api/users/me/liked-boards?page=`는 0-based, size 8, `response.items[{boardId,author,content}]` 및 `totalCount`를 반환한다. `PATCH /api/user/me/nickname`은 `nickname` 1~20자·공백 불가 및 성공 `response.nickname`이다. `DELETE /api/user/me`는 성공 시 계정을 탈퇴시키고 인증 쿠키를 만료한다.
- 실행 Swagger와 실제 서버 응답 검증은 하지 않는다. 계약이 달라지면 호출을 수정하기 전에 충돌을 보고한다.
- 이메일 로그인·가입과 닉네임 변경 응답에는 nickname이 있지만, 확인 가능한 Google OAuth redirect와 JWT에는 nickname이 없고 공개 프로필 조회 API도 없다. Google 로그인 직후 브라우저에 저장된 닉네임은 유지한다. 새 브라우저의 첫 Google 로그인에서 실제 닉네임을 표시하려면 서버의 프로필 조회 계약이 필요하다. 닉네임이 확인되지 않은 세션에는 번역된 `내 계정` 표시를 사용한다.

## 수용 기준

- 인증된 사용자가 헤더에서 마이 페이지에 진입하고, 비회원은 로그인 화면으로 이동한다.
- 네 영역이 데스크톱과 모바일에서 키보드로 탐색 가능하며 한국어·영어 UI 문구를 제공한다.
- 좋아요 목록은 실제 API의 본문·작성자와 페이지 번호를 사용한다. 빈 목록과 오류를 구분한다.
- 닉네임 변경은 필드 검증·중복 오류·처리 상태를 안내한다. 탈퇴는 확인 단계를 거치며 성공 후 로컬 인증을 지운다.
- 개인 태그 목록은 서버 계약이 생기기 전까지 준비 중 상태로 표시한다.
- 사용자가 `cd tag-note-react && npm run test && npm run lint && npm run build` 및 실제 로그인·좋아요·닉네임·탈퇴의 브라우저 동작을 검증한다. 결과를 받기 전에는 `completed/`로 이동하지 않는다.

## 구현 상태

- `/my` route, 로그인 후 헤더 진입, 한국어·영어 문구와 반응형 화면을 구현했다.
- 좋아요 목록 조회·페이지 이동, 닉네임 변경, 기존 로그아웃과 확인 후 탈퇴를 연결했다. 게스트는 로그인 화면으로 보낸다.
- 게스트 전환, 목록 연결, 닉네임 변경, 탈퇴 확인을 검증하는 특성화 테스트를 추가했다.
- 정적 diff 검토와 변경 파일의 `git diff --check`를 수행했다. 테스트·lint·build·브라우저 동작은 사용자 실행 전이므로 완료 처리하지 않는다. 기존 `AUTH-EMAIL-001`도 사용자 검증 대기 상태를 유지한다.
- 후속 UI 수정으로 EXIT를 제거하고 닉네임을 헤더와 페이지 제목에 동기화했다. 이메일 인증·닉네임 변경 응답의 닉네임은 공유 auth 상태와 브라우저 저장소 유틸리티를 통해 유지하고, 로그아웃·탈퇴 시 삭제한다. Google callback의 닉네임 강제 삭제를 제거하고 저장된 닉네임 유지 테스트로 교체했다. 실행 검증은 아직 받지 못했다.
