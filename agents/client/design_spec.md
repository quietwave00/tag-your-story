# #tagnote 디자인 스펙

## 1. 디자인 역할

감각적인 독립 디자인 스튜디오의 디자인 리드로서, 헤비 리스너와 음악 디거를 위한 음악 검색/태그 아카이브 웹 서비스를 설계한다.
목표는 오래된 커뮤니티 게시판이나 개발자 포트폴리오가 아니라, 실제 상용 브랜드 서비스로 보일 만큼 정제된 흑백 기반 인터페이스를 만드는 것이다. 차갑고 현대적인 인상은 유지하되, 과도한 선, 점, 터미널식 문구, 오래된 HTML 게시판 감성은 배제한다.

## 2. 사이트 목적과 사용자

브랜드 이름: `#tagnote`

주요 역할:
- 음악의 기본 정보와 장르 데이터를 구조화하여 조회한다.
- 사용자가 직접 커스텀 태그를 부여해 음악을 아카이빙한다.
- 검색한 트랙, 앨범, 아티스트를 태그 노트와 연결한다.
- 헤비 리스너, 음악 힙스터, 서브컬처 디거가 음악을 깊게 탐색하도록 돕는다.

## 3. 브랜드 태도

전달해야 하는 인상:
- 현대적
- 유려함
- 차가움
- 쿨함
- 상용 브랜드 서비스 수준의 완성도
- 음악 아카이브 스튜디오 같은 집중감

금지 인상:
- 귀여움
- 과한 친근함
- 유머 중심 표현
- 오래된 HTML 게시판
- 터미널/해커 콘솔 감성
- 과도한 dot/noise 패턴
- 과도한 solid line 기반 브루탈리즘

## 4. 핵심 디자인 콘셉트

핵심 키워드:
- modern monochrome
- paper texture
- soft dust
- blurred motion
- shoegaze haze
- editorial archive
- commercial-grade minimalism

디자인은 흑백 신문과 음악 아카이브의 차가운 정밀함을 출발점으로 삼되, 최종 표현은 더 유려하고 상용 서비스답게 정리한다. 점이나 선으로 화면을 채우지 않는다. 질감은 매우 흐린 종이 표면, 뿌연 먼지, 서서히 퍼지는 blur로 표현한다.

## 5. 색상 시스템

주요 색상은 제한된 무채색만 사용한다.

Color Tokens:
- Primary Dark: `#0A0A0A`
- Primary Off-White: `#F2F2F2`
- Paper Gray: `#E9E9E9`
- Muted Text: `#737373`
- Soft Line: `#D1D1D1`
- Hover Invert: `#0A0A0A` background + `#F2F2F2` text

규칙:
- 다채로운 컬러 팔레트는 사용하지 않는다.
- 파스텔, 보라/파랑 그라데이션, SaaS식 컬러 포인트는 사용하지 않는다.
- disabled 상태는 취소선 대신 화면별 light gray 배경·텍스트 또는 opacity로 구분한다.
- 상태 구분에는 색, 굵기, 배경, opacity를 사용한다. 선은 입력·목록 구분 등 필요한 경계에 사용한다.

## 6. 타이포그래피

상용 브랜드 서비스처럼 보이는 네오 그로테스크 계열을 사용한다.

Font Family:
- Display: `Inter Tight`, `Avenir Next`, `Helvetica Neue`, `Helvetica`, `Arial`, `Pretendard`, sans-serif
- Body: `Inter`, `Pretendard`, `Helvetica Neue`, `Helvetica`, `Arial`, sans-serif
- Label/Metadata: 기본적으로 Body와 같은 현대적 산세리프를 사용한다. Monospace는 정말 필요한 숫자/ID/개발자성 메타데이터에만 제한적으로 사용한다.

Typography Rules:
- `Arial Black`처럼 오래된 웹 포스터 느낌이 강한 폰트는 사용하지 않는다.
- 전역 `letter-spacing`은 `0`을 기본값으로 한다. 음수 자간은 사용하지 않는다.
- 페이지 제목은 화면에 따라 `34px ~ 88px` 내외의 반응형 크기를 사용한다.
- 큰 제목은 주로 `760` 안팎의 굵기를 사용하고, 키워드 클라우드처럼 강조가 필요한 곳은 더 굵게 쓸 수 있다. `900`에 일괄 의존하지 않는다.
- 텍스트와 아이템 간 간격은 타이트하게 유지하되, 답답하지 않도록 충분한 섹션 여백을 둔다.

## 7. 레이아웃

기본 레이아웃:
- 주요 콘텐츠의 외곽 폭은 중앙에 두되, 상세 정보·글 본문·마이 페이지 내부의 텍스트와 조작 영역은 각 화면의 읽기 흐름에 맞춰 정렬한다.
- 페이지 폭은 `1120px` 내외로 제한한다.
- 검색, 리스트, 상세, Contact 모두 중앙에 안정적으로 배치한다.
- 섹션 간 여백은 충분히 둔다.
- 아이템 내부 간격은 조밀하게 유지한다.

금지:
- 전역 12-column grid 배경
- 과도한 1px solid line 반복
- 데이터베이스 테이블처럼 보이는 촘촘한 경계선
- 오래된 게시판식 리스트
- 카드 남발

Line Rules:
- 선은 입력 하단선, 버튼/textarea/알림 박스, 섹션 또는 계정 액션의 구분처럼 기능적 경계가 필요한 곳에 사용한다.
- 카테고리 active 상태에 underline을 사용하지 않는다. 굵기와 색으로만 구분한다.

## 8. 질감과 이미지

자산:
- `tag-note-react/assets/tagnote-logo-transparent.png`: 홈 히어로와 공통 헤더·푸터의 브랜드 이미지로 사용한다.
- `tag-note-react/assets/img.png`: 명시적 dot/grain 인상이 강하므로 기본 디자인에서는 사용하지 않는다.

Texture Rules:
- dot 패턴처럼 보이는 noise는 사용하지 않는다.
- 배경 질감은 이미지 대신 낮은 대비의 CSS gradient와 blur로 제한한다.
- 질감은 콘텐츠를 방해하지 않아야 한다.

## 9. 메인 페이지

Header:
- 공통 헤더와 푸터의 브랜드는 `tagnote-logo-transparent.png`를 사용한다.
- 브랜드 오른쪽의 좌측 영역에는 `DIG`만 둔다. `LOG`와 `MY TAGS` 메뉴는 표시하지 않는다.
- 언어 선택 버튼은 헤더에 두지 않는다. 브라우저 언어에서 `ko`/`en`을 자동 감지한다.
- 비로그인 상태에서는 우측 끝에 `LOGIN` 진입을 표시한다. 로그인 상태에서는 작은 기본 아바타와 닉네임 또는 계정 대체 문구로 마이 페이지에 진입하고, 로그아웃은 마이 페이지의 계정 영역에 둔다.
- active underline은 금지한다.

Hero:
- 홈 내부에 별도의 `#tagnote` 텍스트 타이틀을 반복하지 않는다.
- `home-visual-type`처럼 히어로 이미지 위에 `dig/tag/note` 텍스트를 올리는 레이어는 사용하지 않는다.
- 히어로에는 `tagnote-logo-transparent.png`를 중심 브랜드 비주얼로 배치한다.
- 검색 영역은 낮은 높이의 translucent blur panel로 배치한다.
- 첫 화면에서 검색과 많이 찾는 키워드를 함께 인지할 수 있도록 히어로 높이와 섹션 간격을 과도하게 키우지 않는다.

Search:
- 검색 input의 focus는 입력 글자 굵기와 검색 패널의 배경·테두리·그림자 변화로 표현한다. 전역 focus 기본값은 굵기 변화이며 상세 뒤로가기 등 일부 컨트롤은 별도 outline을 사용한다.
- search 버튼 disabled는 light gray, enabled는 dark gray로 구분한다.
- 홈 검색은 하단선 입력 대신 둥근 반투명 패널과 입력·버튼의 간격으로 구분한다. 검색 결과 화면의 입력에는 하단선을 사용한다.

Keyword Cloud:
- 다채로운 pill UI를 쓰지 않는다.
- 흑백 텍스트 중심으로 구성하되, 너무 빽빽한 Wall of Text가 되지 않게 한다.
- hover 시 흑백 반전, 미세한 blur, 작은 이동을 사용한다.

Recent Tags:
- 오래된 게시판처럼 보이지 않도록 선과 번호의 존재감을 최소화한다.
- 중앙 폭 안에서 조밀하지만 정제된 리스트로 구성한다.

## 10. 검색 결과 화면

표현:
- `DATABASE INDEX / 0000 ROWS` 같은 프롬프트성 문장은 금지한다.
- 자연어 UI 문장을 사용한다.
- 중앙 정렬을 유지한다.
- 트랙·앨범 커버는 정돈된 1:1 이미지로, 아티스트 이미지는 원형으로 사용한다.
- 리스트 간격은 타이트하게 유지하되, 테이블 경계선은 사용하지 않는다.

Hover:
- 커버 이미지는 흑백 대비가 살짝 강해진다.
- 결과 항목은 대비·배경·이미지 변화와 미세한 blur로 반응한다. 화면별 실제 hover 표현은 해당 CSS를 따른다.

## 11. 트랙 상세 화면

구성:
- 앨범 커버와 트랙 정보를 중앙 폭 안에서 균형 있게 배치한다.
- 제목은 크지만 과도하게 화면을 압도하지 않는다.
- Artist, Album, Track ID 같은 메타데이터는 산세리프 라벨로 정돈한다.
- 커스텀 태그 노트 리스트는 카드나 테이블이 아닌 가벼운 텍스트 그룹으로 보이게 한다.
- Track의 System Tag 이름은 별도 제목 없이 트랙 제목 위에 배치한다. 각 태그는 `#` 접두사와 둥근 연회색 배경을 갖고, 글자 크기는 이전 큰 태그 표현의 절반인 `clamp(14px, 2.5vw, 32px)`을 사용한다. 태그 노트 목록의 보이는 부제목은 두지 않는다. 미로그인 사용자에게 글 작성 버튼은 비활성 스타일로 보이되 클릭하면 로그인 안내 문장을 표시한다.
- 트랙·앨범·아티스트 상세에서는 대표 이미지에서 2~3가지 색을 뽑아 뷰포트 전체의 하단에서 위로 옅어지는 배경으로 사용한다. 현재 읽는 화면 중앙은 밝은 무채색 층을 유지해 제목, 메타데이터, 태그, 목록을 선명하게 읽을 수 있게 한다. 색 추출이 불가능하면 흐린 이미지 배경을 사용하고, 이미지가 없으면 기존 무채색 배경을 유지한다.
- 대표 이미지 배경이 활성화된 상세 화면에서는 footer를 투명하게 두어 색 흐름이 끊기지 않게 한다. 트랙의 게시글 카드와 태그, 앨범 상세의 트랙 행 및 아티스트 상세의 앨범 행 hover는 반투명한 밝은 면과 배경 블러를 사용한다. 글자와 이미지는 직접 흐리게 하지 않으며 키보드 focus 윤곽은 유지한다.

## 12. 글 작성/상세/댓글

글 작성:
- textarea 정도에만 기능적 경계선을 허용한다.
- 태그와 선택 항목의 둥근 모서리는 해당 화면 CSS의 기존 형태를 따른다. 전역으로 `2px` radius를 강제하지 않는다.
- 파일 프리뷰는 이미지 자체가 중심이 되게 하고 선을 남발하지 않는다.

글 상세:
- 본문을 중앙의 흰 읽기 면에 배치한다. 작성자 아바타·닉네임·날짜는 상단 좌측, User Tag는 상단 우측에 놓고 얇은 구분선 아래에 본문을 둔다. 별도 우측 정보 열이나 포스터형 정렬을 만들지 않는다.
- 본문은 일반 텍스트 크기와 넉넉한 행간으로 읽히게 한다. 본문 아래 기능적 구분선을 두고 하트 좋아요를 배치한다. 좋아요에 기본 배경색을 강제하지 않으며 수정·삭제는 조용한 텍스트 버튼으로 둔다.
- 댓글 제목·입력·목록은 카드 아래에서 카드의 바깥 폭과 시작점을 맞춘다.

글 수정:
- 상세 화면의 `.detail-page-frame`과 흰 읽기 면, 작성자·날짜 헤더, 본문 폭·행간을 그대로 사용한다. 뒤로가기 버튼도 상세 화면과 같은 시작점에 둔다.
- 상세 화면의 태그 자리는 태그 입력 영역으로 바꾼다. 기존 태그는 같은 회색 배경의 버튼으로 보여주고 클릭하면 삭제한다. 입력 중 경고와 키보드 focus가 분명해야 한다.
- 본문을 카드 안에서 직접 수정한다. 기존 이미지가 있을 때만 본문 뒤에 미리보기와 삭제 조작을 표시하며 이미지 업로드 버튼은 두지 않는다. 저장·취소는 카드 하단 오른쪽에 둔다. 댓글·좋아요는 수정 화면에 표시하지 않는다.

댓글:
- 댓글 수는 제목 옆에 보조색으로 표시한다. 입력과 작성 버튼은 하나의 흰색 둥근 입력 면에 놓는다.
- 각 댓글은 작은 작성자 아바타, 닉네임, 가능한 경우 작성 날짜, 본문 순서로 읽히게 한다. 행 사이에는 옅은 선을 쓰고 답글·수정·삭제는 보조 액션으로 둔다.

## 14. 인터랙션

기본 원칙:
- UI는 너무 딱딱하지 않아야 한다.
- hover와 page enter에서 opacity·blur·transform을 조합한다. 홈과 상세 화면마다 강도와 타이밍을 다르게 사용한다.
- 움직임은 유려하지만 장식적 parallax처럼 과하지 않아야 한다.

Motion:
- page enter: `globals.css`의 `page-bloom`처럼 opacity와 `blur(18px) -> blur(0)`을 약 `420ms`에 걸쳐 전환한다.
- home logo와 검색 패널은 각각 blur·opacity·translate로 등장한다.
- 홈 섹션은 뷰포트 진입에 맞춘 `section-rise`를 사용한다.
- hover: 흑백 반전, 미세한 blur, 작은 translate를 화면별로 조합한다.

Timing:
- `linear` 또는 절제된 ease를 사용한다.
- 공통 page bloom은 `420ms`, 홈 로고·검색 패널·섹션 등장은 약 `480~550ms`, 아티스트 캐러셀 전환은 약 `720~760ms`를 기준으로 한다.
- 클릭 피드백은 과장하지 않는다.

## 15. 금지사항 요약

- 이전 브랜드명 사용 금지. 브랜드는 `#tagnote`.
- `home-visual-type` 텍스트 레이어 사용 금지.
- dot/noise 패턴을 주 시각 요소로 사용 금지.
- `img.png`를 기본 dust로 사용 금지.
- 과도한 solid line grid 금지.
- active nav underline 금지.
- disabled 취소선 금지.
- 프롬프트성 문구 금지: `DATABASE INDEX`, `0000 ROWS`, `SCRAPED METADATA`, `STREAM`, `GRID`, `NOISE 03` 등.

## 16. 현재 React 구현의 화면 패턴

이 절은 2026-11-02 `tag-note-react/src`의 컴포넌트와 CSS를 기준으로 기록한다. 앞 절의 추상적인 표현과 다르면 실제 구현에 맞는 이 패턴을 우선한다. 디자인 변경은 해당 컴포넌트와 CSS를 함께 갱신한다.

- **공통 셸:** `AppLayout`은 상단 로고, DIG, 알림, 비로그인 LOGIN 또는 로그인한 사용자의 닉네임, 푸터 로고와 Contact 링크로 구성된다. 로그인 상태의 로그아웃은 `MyPage`의 계정 섹션에 있다. 내비게이션 활성 상태는 밑줄 대신 글자색으로 구분한다. 헤더 언어 선택기는 없으며 브라우저 언어로 한국어/영어를 감지한다.
- **홈:** 로고 이미지가 히어로의 중심이고 검색 폼은 반투명한 둥근 패널이다. 검색 폼은 데스크톱에서 입력과 버튼을 나란히, `767px` 이하에서 세로로 배치한다. 키워드 클라우드는 크기가 다른 흑백 텍스트 버튼이고, 최근 태그는 번호와 텍스트 중심의 목록이다.
- **검색:** 유형별 결과를 한 화면에 구분해 배치한다. 트랙·앨범은 사각 커버, 아티스트는 원형 이미지 계열로 표현한다. 입력은 하단선 중심이며 결과와 아티스트 캐러셀은 별도 움직임을 갖는다.
- **상세와 게시글:** Track·Artist·Album·Board는 `.detail-page-frame`의 최대 폭 `980px`와 같은 뒤로가기 시작점을 공유한다. 트랙·아티스트·앨범은 대상 이미지와 이름을 우선 배치한다. Board 상세는 흰 읽기 면의 작성 정보·태그·본문·하트 좋아요 순서와 카드 아래 댓글의 같은 바깥 폭을 따른다. Board 수정은 같은 카드·헤더·본문 안에서 태그와 내용을 편집하며 좋아요와 댓글은 보이지 않는다. 글 작성의 태그·미리보기·선택 화면은 기존 `boardEdit.css`의 표현을 따른다.
- **태그 노트 목록:** Track 상세의 각 Board는 hover 전에도 옅은 회색 배경을 가지며 태그마다 별도 배경을 둔다. 본문은 짧게 미리 보여준다. 메타 행에서는 닉네임·작성 날짜를 왼쪽 같은 기준선에, 좋아요 수·댓글 수를 오른쪽에 묶는다. 좁은 화면에서 줄이 바뀌어도 수치 묶음은 오른쪽 정렬을 유지한다. 서버에서 수치를 가져오지 못한 항목은 임의의 `0`으로 채우지 않는다.
- **인증과 마이 페이지:** 인증은 중앙 정렬 패널, 입력 하단선, 흑백 버튼을 사용한다. 마이 페이지는 데스크톱에서 좌측 섹션 내비게이션과 우측 내용, `700px` 이하에서 위쪽에 줄바꿈되는 내비게이션을 사용한다. 빈 상태·좋아요 항목·탈퇴 확인 영역에는 밝은 회색 표면과 둥근 모서리를 쓴다.
- **Contact:** 공통 푸터에서 진입한다. `GITHUB`, `SPOTIFY`, `INSTAGRAM`, `EMAIL` 링크를 제공하며 문의 폼은 없다.

## 17. 토큰과 상태 표현의 실제 기준

- 공통 색상·서체·폭은 `src/styles/globals.css`의 CSS 변수에서 가져온다. 밝은 배경 `#F2F2F2`, 본문 `#0A0A0A`, 보조 문구 `#737373`, 종이색 `#E9E9E9`, 부드러운 선 `#D1D1D1`, 스켈레톤 `#E4E4E4`를 사용한다. 본문 최대 폭은 `1120px`, 좁은 영역은 `760px`이다.
- 둥근 모서리는 화면 역할에 따라 다르다. 전역 버튼 기본 `6px`, 헤더 링크와 홈 검색 버튼 `12px`, 홈 검색 패널 `18px`, 글 상세 표면 `20px`, 알림 패널 `16px` 등 현재 CSS 값이 기준이다. 모든 요소를 하나의 radius로 통일하지 않는다.
- 배경은 밝은 무채색 gradient, 반투명 표면, `backdrop-filter`와 제한적인 그림자를 조합한다. 커버 이미지와 태그·음악 이름은 실제 콘텐츠의 색과 글자를 보존한다.
- 현재 CSS는 hover에서 반전·blur·translate를 사용한다. `:focus-visible`은 전역에서 굵기를 올리고 일부 컨트롤에서 별도 배경 또는 outline을 사용한다. `prefers-reduced-motion` 처리는 검색·상세·글 작성·마이 페이지 CSS에 각각 존재하며 전역 공통 규칙은 없다. 이 설명은 구현 현황이며 접근성 검증 결과를 뜻하지 않는다.
- **데이터 로딩:** 모든 데이터 조회 영역은 로딩 문장만 노출하지 않고 실제 콘텐츠의 이미지·제목·메타·행·카드 구조에 맞춘 스켈레톤을 표시한다. 검색, 홈 랭킹·최근 태그, 상세 헤더·태그·목록, 게시글·댓글, 알림, 마이페이지 목록에 적용한다. 공통 `.skeleton-block`은 연한 단색 무채색 면과 약 `2.8초` 주기로 천천히 밝아졌다 어두워지는 opacity pulse를 사용하며 스켈레톤 내부에 그라데이션을 넣지 않는다. `prefers-reduced-motion`에서는 움직임을 멈춘다. 스켈레톤은 `aria-hidden`으로 읽기 순서에서 제외하고 영역의 번역된 로딩 문구는 시각적으로 숨긴 `role="status"`로 알린다. 로딩 중 이전 데이터가 새 결과처럼 보이지 않게 한다.
- **다른 상태:** 빈 상태·오류는 명시적인 문장으로 남기고, 저장·삭제처럼 사용자가 시작한 작업의 진행 상태는 해당 버튼이나 작업 영역에서 표현한다. 홈 랭킹 요청이 비어 있을 때의 fallback 키워드와 오류 문구도 현재 동작에 포함된다.

## 18. 디자인 문서 갱신 기준

- 화면을 바꿀 때는 해당 page·component와 CSS의 실제 값, 공통 토큰, 모바일 미디어 쿼리를 확인한 후 이 문서의 관련 항목을 갱신한다. 기존 UI를 버리고 새 스타일을 일괄 적용하지 않는다.
- UI 문구는 `ko`·`en` 번역 리소스를 사용하고, User/System Tag 이름·검색어·음악명·닉네임·글과 댓글 본문은 원문을 유지한다.
- 실제 화면 캡처와 브라우저 조작을 하지 않은 코드 검토는 시각 감사나 접근성 통과 판정으로 기록하지 않는다.

## 19. 상용 서비스 화면 구성 기준

Board 상세의 시각 참조는 `agents/client/img.png`다. 이 이미지는 사용자 제공 목표 화면으로 사용한다. 수치와 비율은 화면 폭에 맞게 조정하되 아래 관계를 유지한다.

- **면과 폭:** 상세 콘텐츠는 공통 `.detail-page-frame` 안에 둔다. 한 화면의 주 콘텐츠에 흰 읽기 면 하나를 사용하고, 옅은 회색 페이지 배경·낮은 대비의 그림자·약 `20px` 둥근 모서리로 깊이를 만든다. 댓글은 읽기 면 아래에 같은 좌우 시작점으로 연결한다. 장식용 카드를 반복하지 않는다.
- **정보의 순서:** 글에서는 작성자와 날짜 → 태그 → 본문 → 반응과 관리 액션 순서가 한눈에 읽혀야 한다. 약 `40px` 작성자 아바타와 약 `28px` 댓글 아바타는 닉네임의 첫 글자를 표시하는 기본 표현이다. 아바타는 닉네임 텍스트를 대신하지 않는다.
- **타이포그래피:** 글 본문은 약 `17px`의 일반 산세리프와 넉넉한 행간, 댓글 본문은 약 `14px`로 둔다. 닉네임은 분명하게, 날짜·댓글 수 같은 보조 정보는 작고 낮은 대비로 둔다. 사용자 본문과 태그의 원문 표기를 보존한다.
- **구분:** 읽기 면의 상단 정보와 본문, 본문과 반응 사이에만 얇은 선을 둔다. 댓글 행은 옅은 선과 간격으로 구분한다. 선이 화면 전체를 지배하지 않게 한다.
- **조작:** 좋아요는 하트와 수를 함께 보여주되 기본 배경 없이 둘 수 있다. 댓글 입력과 작성 버튼은 하나의 흰 입력 면 안에 놓고 disabled·focus·작성 중 상태를 구별한다. 수정·삭제·답글은 본문보다 낮은 시각 위계로 유지한다.
- **반응형:** 좁은 화면에서는 작성 정보와 태그를 줄바꿈하고 카드 안쪽 여백을 줄인다. 댓글 입력과 작성 버튼은 같은 면 안에 남기며 가로 스크롤이나 본문 잘림이 없어야 한다. 상세 본문과 댓글의 시작점 관계를 유지한다.
- **적용 범위:** 이 비율과 시각 위계는 새 상세·커뮤니티 화면을 설계할 때 참조한다. 화면 고유의 정보 구조와 기존 공통 컴포넌트를 확인한 뒤 적용하며, 기능·API 계약을 시각 기준만으로 바꾸지 않는다.
- **검토:** 향후 화면 변경은 데스크톱·태블릿·작은 모바일에서 같은 콘텐츠 순서와 시작점을 비교한다. 긴 닉네임·여러 태그·긴 본문, 댓글 없음·로딩·오류, 로그인 전후, 키보드 focus와 한국어·영어를 확인한다. 화면 캡처가 없으면 이미지와 일치한다고 판정하지 않는다.
